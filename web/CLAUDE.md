# forky web

The operator web UI for forky — a React single-page app that visualizes
Ethereum Beacon Chain fork-choice data. Built with Vite and embedded into the
forky binary (see the repo-root `CLAUDE.md`).

## Commands

pnpm is the package manager.

```bash
pnpm install
pnpm dev            # Vite dev server (proxies /api to a backend; see vite.config.ts)
pnpm dev:mock       # dev server with MSW mocks (VITE_MOCK=true)
pnpm build          # type-check + build production assets into dist/ (embedded by the Go binary)
pnpm preview        # preview the production build
pnpm lint           # eslint
pnpm typecheck      # tsc --noEmit
pnpm format         # prettier --write src
pnpm test           # vitest
pnpm generate:api   # regenerate the typed API client from ../api/openapi.yaml
```

## Stack

- pnpm, Vite 8, React 19, TypeScript 6
- @tanstack/react-router (file-based routing), @tanstack/react-query
- Tailwind CSS v4 (via @tailwindcss/vite)
- graphology (graph data structures + layout) for the fork-choice visualization
- MSW for API mocking in dev/tests; Vitest for tests
- @hey-api/openapi-ts + zod for the generated, typed API client

## API client

The OpenAPI spec at `../api/openapi.yaml` is the source of truth — the Go
server is generated from the same spec (ogen), so the wire format matches by
construction and SDK responses are validated against the zod schemas at
runtime. Run `pnpm generate:api` (or `make generate` at the repo root) to
regenerate the typed client, TanStack Query helpers and zod schemas into
`src/api/` (do not edit by hand — the whole directory is generated). Runtime
client config (base URL, fetch) lives in `src/utils/api-config.ts`. MSW mocks
in `src/mocks/` are typed against the generated response types, so tests fail
if the mocks drift from the spec.

Domain hooks in `src/hooks/useQuery.ts` wrap the generated SDK and adapt
responses to the app's view types — components consume those hooks, not the
generated client directly.

## Routing

TanStack Router with file-based routes. `src/routes/` holds the route
definitions (`__root.tsx`, `index.tsx`, `byo.tsx`, `events.tsx`, `node.$.tsx`,
`snapshot.$frameId.tsx` and the non-nested `_.events` variants);
`routeTree.gen.ts` is generated by the Vite plugin. Forky's URL scheme models
top-level views (`/byo`, `/node/<id>`, `/snapshot/<id>`) and route-specific
event overlays (`/events`, `/byo/events`, `/node/<id>/events`,
`/snapshot/<id>/events`). Node ids contain literal slashes
(`ethpandaops/mainnet/node-001`), so `/node` is a splat route (`node.$.tsx`)
whose remainder is the node id plus an optional trailing `/events` overlay
segment (parsed by `parseNodeSplat` in `src/utils/routes.ts`).

The root route renders the single, persistent `<App>` for every view and
derives view props from the location via `parseAppRoute`; the leaf route
files are matchers only (they render nothing). This keeps one App — and the
focus provider that owns the player's focused time and play/pause state —
mounted across navigation, so switching between aggregated, node and
snapshot views never resets playback. Don't add `component`s to leaf routes;
add new views to the `parseAppRoute` switch in `__root.tsx` instead.
`src/hooks/useAppNavigation.ts` (`usePathname`, `useAppNavigate`) and
`src/components/Link.tsx` remain the app's routing primitives for components
that pass plain path strings.

## Structure

```
src/
  api/            # generated, typed API client (do not edit)
  routes/         # TanStack Router route definitions + routeTree.gen.ts
  components/     # React components (graph nodes, summaries, controls, ...)
  contexts/       # React contexts (ethereum, focus, selection)
  providers/      # Context providers
  hooks/          # Custom hooks (useQuery, useGraph, useActive, useLocation, ...)
  parts/          # Page sections (Graph, Header, Timeline, Stage, ...)
  utils/          # Helpers (graph, maths, strings, api-config, ...)
  types/          # Shared TypeScript view types
  index.css       # CSS entry: Tailwind + two-tier color tokens (see Theming)
  mocks/          # MSW handlers
  index.tsx       # Entry point (QueryClientProvider + RouterProvider)
```

## Conventions

- Path aliases (`@app/*`, `@api`, `@components/*`, `@hooks/*`, ...) — see
  `tsconfig.app.json`. Prefer aliases over deep relative imports.
- Theming: colors follow a two-tier token architecture in `src/index.css` —
  Tier 1 primitive values feed Tier 2 semantic tokens (`bg-surface`,
  `text-foreground`, `text-canonical`, ...). Application code may only use
  the semantic tokens and never writes `dark:` variants for colors (light and
  dark values flip via CSS variables on `html.dark`). Enforced by the custom
  ESLint rules in `eslint-rules/`.
- Run `pnpm lint` and `pnpm build` before committing.
